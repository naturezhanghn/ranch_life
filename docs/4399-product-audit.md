# 4399 风格网页游戏首轮产品审计

这份审计把常见的 4399 休闲网页游戏体验目标转成可检查的工程项。它不是平台官方认证清单，适合用于本项目的首轮产品化重构。

## 当前优势

- 页面已经有明确的首屏标题、继续游戏、新游戏和操作说明。
- Canvas、弹窗、顶部状态栏、目标卡、触屏方向键和行动按钮已经形成完整框架。
- 游戏逻辑具备本地存档、日结、任务、员工、场景、小游戏和移动端输入。
- `npm run build` 能执行语法、资源和核心玩法回归检查，适合继续做小步发布。

## P0 首轮必须完成

### 首次进入

- 首次加载显示明确的加载状态，等待 Canvas、字体和音频初始化完成后再启用开始按钮。
- 新玩家进入后只展示三个动作提示。移动、靠近目标、按行动键。其余系统分批解锁，避免开场信息过载。
- 开场任务卡必须显示当前地点、目标、下一步动作和奖励。完成后立刻出现短反馈并自动切换到下一目标。
- 继续游戏按钮显示存档日期、季节、地点和最近目标，避免玩家不知道要从哪里继续。

### 核心操作

- 所有可操作对象都必须有统一的距离高亮、按钮提示和成功反馈。
- 触屏行动按钮必须跟随当前最近交互对象更新文案。它不能长期只显示“行动”。
- 工具、种子、员工、房屋和场景按钮必须有禁用态原因。金币不足、体力不足、场景未解锁和库存不足都要在按钮旁说明。
- 关键操作支持重复点击保护，避免双击购买、重复领取奖励和重复提交出货。

### 任务和留存

- 主线、每日任务、周请求和员工日结必须在同一处提供可读摘要。
- 日结需要展示作物变化、牲畜照料、员工动作、工资、金币变化和下一天提醒。
- 每天至少提供一个短目标和一个可选活动，玩家无需阅读长文本也能继续经营。
- 任务失败、错过时段和资源不足必须给出可恢复路径，不能把玩家锁死在主线外。

### 加载与性能

- 首屏只加载当前场景和核心界面，非当前场景素材延迟加载。
- Canvas 动画必须在页面隐藏、低电量或低帧率时降频。粒子优先级低于玩家、员工和交互高亮。
- 图片资源统一通过 `assets/manifest.json` 校验大小、存在性和加载路径。
- 保存动作采用节流和备份存档，页面关闭、切换场景、日结和关键奖励后都要有可靠写入。

## P1 第二轮改造

### 界面层级

- 顶部只保留日期、天气、金币、体力、水量和当前场景。复杂系统放入菜单或场景面板。
- 目标卡、交互提示和触屏按钮不应遮挡玩家、作物和员工。移动端使用安全区和动态底部偏移。
- 弹窗按钮统一为主操作、次操作和关闭三种层级。危险操作需要二次确认，普通操作不应要求二次确认。
- 任务、员工、房屋、库存和订单面板采用相同的卡片结构，标题、状态、成本、收益和操作位置固定。

### 反馈和动效

- 收获、播种、喂养、工资、交易和场景切换都有轻量音效、浮字或粒子反馈。
- 员工工作动作要与日结数据一致。视觉上显示播种时，日结必须记录播种数量。
- 任务完成和章节推进采用短动画，时间控制在 0.2 至 0.6 秒，支持减少动态效果设置。
- 失败反馈必须说明修复方法，例如“水罐不足，去旧水渠取水”，不能只显示“失败”。

### 移动端

- 目标尺寸至少 44px，方向键、行动键和工具栏之间留出防误触间距。
- 竖屏时优先保证玩家、交互提示、行动键和工具栏可见。复杂弹窗支持滚动且不被键盘遮挡。
- 横屏时保留完整地图视野，顶部信息和底部工具栏不能覆盖交互热点。
- 触屏按住移动、滑动取消、弹窗关闭和小游戏退出都要有明确状态。

## P2 商业化和运营基础

- 记录首日完成率、第一次种植、第一次照料、第一次雇员、第一次进入房屋和第一次日结等本地事件，后续接入统计时不改变玩法。
- 每周任务、季节活动和员工故事使用数据驱动配置，方便不改核心代码就增加内容。
- 所有奖励发放接口保持幂等，刷新、重复点击和断网重试不能重复发放。
- 线上部署保留版本号、构建时间和最近提交，出现问题时可以快速确认页面版本。

## 验收门禁

每次发布前至少运行以下检查。

```bash
npm run build
npm run story-paths
git diff --check
```

人工验收覆盖新游戏、继续游戏、进屋、做饭、看电视、玩游戏、睡觉、雇员、员工日结、收获后自动播种、杂草恢复、移动端触摸和页面刷新存档。

## 推荐首轮交付顺序

1. 新手引导和加载状态
2. 交互提示、任务卡和日结摘要
3. 移动端触控和弹窗安全区
4. 员工、作物和牲畜反馈一致性
5. 资源加载、存档备份和性能降级
6. 事件埋点和版本信息
